### context-clock
**Deliverable:** setting `?contextDate=` to a prior month makes the dashboard actually resolve that
month's tracker — the documented month-boundary test mechanism starts working on the one screen
where it was silently ignored.
**Why paired:** findings 1 and 2 are one fix. The bug *is* the duplication: the bonus path grew
`bonusContextDate_` and the other six sites did not. Fixing 1 without 2 re-arms it.
**Must not:** change the server's `resolveContextDate_` precedence chain, or the PROD refusal.
**Work-log:** per-stage.

### tool-hygiene
**Deliverable:** one Axiom query tool, and a repo root that matches the Document Map.
**Why paired:** the duplicate tool survived *because* of the root clutter — ambiguous filenames at
the root are the mechanism. Clearing both in one pass is what stops it recurring.
**Must not:** delete anything with historical value — `docs/archive/` exists.
**Work-log:** one entry covering both beads.

### dashboard-perf
**Deliverable:** measurably lower `rosterLoopMs` and a smaller dashboard payload, both readable
from telemetry that already exists — no new instrumentation needed to prove either.
**Why paired:** both are pure-function changes on the dashboard build path with existing unit
tests as the net, and both are verified from the same telemetry event.
**Must not:** touch `bonusByTypeSeries`' shape — it is what makes date-nav scrubbing round-trip-free.
**Work-log:** one entry covering both beads.

### request-memo
**Deliverable:** one property-store fetch and one Config read per request instead of several —
and SIT timing that means something, because it stops paying a cost PROD never pays.
**Why paired:** the same idiom applied twice (request-scoped memo, GAS's one-execution-one-request
guarantee stated explicitly in each docstring). Settling the pattern once is the point.
**Must not:** introduce a memo without an invalidation path from every write wrapper.
**Work-log:** one entry covering both beads.

### scorecard-stability
**Deliverable:** a team keeps its colour and its place between loads — "we're the green team"
becomes learnable.
**Why paired:** single bead; the colour fix and the sort tiebreak are one user-visible defect.
**Work-log:** per-stage.

### split-cache
**Deliverable:** the alias preamble stops being hand-written per symbol, and the CacheService key
strings get one home instead of three literals apologising for each other.
**Why paired:** the helper lands first so the first extraction consumes it rather than copying the
old preamble into a new file.
**Must not:** change any cache key string or TTL while moving it.
**Work-log:** per-stage.

### split-identity
**Deliverable:** `dashboardWebapp.js` down to roughly 1,700 lines with clean seams.
**Why paired with `split-cache` rather than merged into it:** three extractions are three instances
of one conversion, which the batching anti-pairing forbids in a single session. `siteFeedback.js`
rides along here because at 60 lines and zero coupling it is not a real second instance.
**Must not:** change behaviour — the existing unit tests are the entire regression net.
**Work-log:** per-stage.

### admin-dispatch
**Deliverable:** `Object.keys(ADMIN_ACTIONS_)` as a real coverage oracle, so the entry-point
registry stops being kept in sync by hand.
**Why after the splits:** same file family; the module-alias pattern should be settled before a
second structural change lands on it.
**Work-log:** per-stage.

### test-tier
**Deliverable:** a failing run names the AC that regressed, and the H6/H7/H8 denominators count
cases rather than files.
**Why paired:** both are test-tier reuse work, both migrate on touch rather than in one sweep, and
both want the runner-level decision made up front.
**Must not:** convert all 63 files in one commit.
**Work-log:** per-stage.

### observability
**Deliverable:** data on whether global-lock contention is real at current scale, and an alert if
an admin secret is ever bootstrapped unexpectedly on PROD.
**Why paired:** both are instrument-then-decide, neither is a fix. Findings 14 and 15 are recorded
residual risks; acting on either without data would be speculation, and 14's mitigation is an ADR.
**Must not:** restructure the lock, or change the bootstrap flow.
**Work-log:** per-stage.
